This assignment helped me understand data lineage as a practical design rule, not just a definition. Each cleaning step uses an element function with `Series.apply` to make a new numeric column while keeping the original text beside it. Starting with `.copy()`, adding a column, and returning the copy made it easier to reason about each step and avoid changing the caller's DataFrame. I also had to distinguish `Series.apply` for cleaning one value at a time from `DataFrame.apply(axis=1)` for gross pay and pay type, which need both hours and rate from the same row. The merge was challenging because the timesheet and roster have different grain: one row per person who worked that week versus one row per employee. Thinking through the business rule made the join choice clearer. A left merge keeps every timesheet row, including an unknown employee, and gives that row `NaN` roster values instead of silently losing it. Checking for a missing rate before calculating pay or classifying overtime also matters: an unmatched employee should be flagged, not accidentally treated as a normal or overtime paycheck. The parser functions reinforced the idea to coerce unreadable values to zero so one malformed cell does not stop the whole pipeline. One debugging lesson came from the structure test for the app. It flagged `.drop_duplicates()` even though I was only deduplicating IDs for the warning, because the AST check looks for that method name anywhere in the file. Replacing it with `.unique()` kept the warning behavior and satisfied the check. That reminded me to read the assertion and failure message closely, and to distinguish a structural test from a runtime behavior test. Next, I want to practice tracing a row through the full copy-add-return pipeline, especially how a missing match travels from the left merge through `NaN`, `pay_type`, the boolean-indexed payable rows, and the export. I can do that by stepping through a small hand-built DataFrame with both a matched ID and an unknown ID, then checking each intermediate frame and the exported columns.
